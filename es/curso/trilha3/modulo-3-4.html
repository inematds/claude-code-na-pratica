1

🗺️ Qué es un «OS personal» para IA

A medida que usas Claude Code, las piezas se multiplican: varios proyectos, decenas de skills, agentes especializados, varias suscripciones. En algún momento pierdes la visión del conjunto. El "sistema operativo personal" es la capa que te devuelve esa perspectiva; no es un producto que compras, sino una combinación de cosas simples que reúnes por tu cuenta.

Qué es:

Carpeta raíz + CLAUDE.md maestro + panel visual que ofrece una visión única de tu uso de Claude Code.

Por qué aprender:

Sin esta capa, cada proyecto es una isla; no sabes cuántas skills tienes ni cuánto gastas. Con ella, trabajas con un mapa, no a ciegas.

Conceptos clave:

Panel (dashboard) · fuente única de verdad · sistema = datos + visualización (no una aplicación cerrada) · «empieza poco a poco y crece».

🚗 Analogía del tablero del auto

No miras dentro del motor todo el tiempo; miras el tablero: velocidad, combustible, temperatura. Tu tablero de IA hace lo mismo: cuántos proyectos activos tienes, qué skills existen, cuánto gastaste este mes y qué suscripción está infrautilizada.

📌 Analogía del tablero de anuncios

O CLAUDE.md el maestro es el tablero de la entrada: todos los que llegan lo leen primero. Indica dónde están las cosas y cuáles son las reglas. El panel HTML es la «vitrina» de ese tablero: la versión bonita e interactiva.

⭐ La regla de oro

El sistema es tuyo, así que empieza poco a poco y crece según la demanda. No intentes reproducir un panel lleno de funciones el día 1. Arma la estructura, un CLAUDE.md maestro y una página que muestra tres cosas. Después agregas costos, onboarding, agente. Cada pieza es opcional y reemplazable.

2

📁 La estructura de carpetas: la columna vertebral

El panel solo puede mostrar lo que está organizado. Por eso, la estructura de carpetas va antes que todo: una carpeta raíz con subcarpetas para proyectos, skills, agentes, conocimiento, el panel y —la pieza clave— una carpeta dados/ con archivos simples que el panel y Claude leen.

Qué es:

Una carpeta raíz (p. ej., meu-os/) con subcarpetas por categoría y una dados/ para los archivos JSON.

Por qué aprender:

La estructura es lo que hace posible y automatizable todo lo demás. Sin ella, el panel no tiene nada que leer.

Conceptos clave:

Carpeta raíz como índice · una subcarpeta por categoría · datos en formato simple (JSON/markdown) que el panel y Claude leen.

Estructura sugerida de la carpeta raíz

meu-os/
├── CLAUDE.md            ← o "quadro de avisos" (mestre)
├── projetos/            ← um diretório por projeto seu
├── skills/              ← suas skills
├── agentes/             ← seus subagentes
├── conhecimento/        ← memória longa (notas, referências)
├── dados/               ← o painel LÊ daqui
│   ├── projetos.json
│   ├── skills.json
│   ├── agentes.json
│   └── custo.json
└── painel/
    └── index.html       ← a "vitrine" clicável

3

📋 El CLAUDE.md maestro: quién manda en el conjunto

O CLAUDE.md en la raíz del meu-os/ é o cerebro del sistema: describe dónde está cada cosa, las reglas generales y cómo Claude debe actualizar los datos. Cuando pides «actualiza mi panel» en cualquier chat, Claude lee este archivo y sabe exactamente qué hacer.

Qué es:

Un archivo breve en la raíz que describe todo el sistema: mapa de carpetas, reglas e instrucciones de mantenimiento.

Por qué aprender:

Es la fuente de verdad que hace que el sistema obedezca comandos en lenguaje natural, en cualquier chat nuevo.

Conceptos clave:

Mapa de carpetas · reglas globales · instrucciones de mantenimiento ("al agregar una skill, regístrala en dados/skills.json") · queda corto y estable (~250 palabras).

Esqueleto del meu-os/CLAUDE.md (~250 palabras)

# Meu OS pessoal — Claude Code

## Mapa de pastas
- projetos/      → um diretório por projeto
- skills/        → minhas skills
- agentes/       → meus subagentes
- conhecimento/  → memória longa
- dados/         → JSON que o painel lê
- painel/        → index.html (a vitrine)

## Arquivos de dados
- dados/projetos.json  → nome, status, objetivo
- dados/skills.json    → nome, descrição, modelo
- dados/custo.json     → serviço, gasto, % de uso

## Regras de manutenção
- Ao adicionar projeto/skill/custo, edite SÓ o JSON
  correto em dados/.
- Nunca invente preços ou valores — pergunte se faltar.
- Mantenha este arquivo curto; detalhes vão nos JSON.
Profundiza (opcional): ¿por qué ~250 palabras?

Un CLAUDE.md inflado se lee por completo en cada chat: consume contexto y envejece rápido. Mantén solo lo que es estable (mapa + reglas). Todo lo que cambia a cada rato (la lista de proyectos, los gastos) vive en los JSON de dados/ y en conhecimento/, que Claude lee solo cuando lo necesita.

4

🖥️ El panel HTML que lee JSON: el escaparate interactivo

El panel es una página única index.html que lee los archivos de dados/ y muestra tarjetas de proyectos, una lista de skills/agentes y un resumen de costos. Sin build, sin backend, sin framework: se abre directamente en el navegador (file://) y transforma datos crudos en el "tablero del auto".

Qué es:

Una página que carga JSON local mediante fetch y muestra bloques visuales; Claude genera y actualiza el HTML por ti.

Por qué aprender:

Es lo que te permite mirar rápidamente y entender tu uso, en vez de abrir cinco archivos.

Conceptos clave:

Una página · sin build/backend · lee JSON mediante fetch · empieza con tres bloques: Proyectos, Skills, Costo del mes.

Ejemplo de panel — corazón del painel/index.html

<div id="projetos"></div>
<div id="custo"></div>

<script>
async function carregar() {
  // lê os JSON de dados/ (caminho relativo ao index.html)
  const proj  = await fetch('../dados/projetos.json').then(r => r.json());
  const custo = await fetch('../dados/custo.json').then(r => r.json());

  // cards de projetos
  document.getElementById('projetos').innerHTML =
    proj.map(p => `<article><b>${p.nome}</b> — ${p.status}</article>`).join('');

  // soma de custo + alerta de subuso
  const total = custo.reduce((s, c) => s + c.gasto, 0);
  const subuso = custo.filter(c => c.uso < 40);
  document.getElementById('custo').innerHTML =
    `Total do mês: R$ ${total.toFixed(2)}` +
    (subuso.length ? ` · ⚠️ subutilizado: ${subuso.map(c => c.servico).join(', ')}` : '');
}
carregar();
</script>

Maqueta ilustrativa — Claude arma todo el HTML y el estilo por ti; lo que importa es el patrón: leer JSON → renderizar → sumar/alertar.

💡 Consejo práctico

Algunos navegadores bloquean fetch de archivos locales por seguridad. Si el panel se abre vacío en file://, pídele a Claude que inicie un servidor local sencillo (una línea) o que incruste los datos directamente en el HTML mientras haces las pruebas.

5

💸 Seguimiento del costo y el uso entre modelos

O dados/custo.json é o medidor de combustible: registras gastos y uso por modelo/suscripción, y el panel suma y destaca el uso insuficiente. Aquí es donde el sistema «se paga solo»: ver una suscripción infrautilizada puede hacer que cambies de plan y ahorres.

Qué es:

Un archivo con un elemento por servicio (modelo, gasto, % de uso) que el panel suma y analiza.

Por qué aprender:

Es el retorno más concreto del sistema: claridad sobre en qué se está gastando el dinero de IA (y dónde está detenido).

Conceptos clave:

Registro manual o semiautomático · un elemento por servicio · campos de gasto y uso · los precios provienen de la página oficial — nunca inventes valores.

Ejemplo de dados/custo.json

[
  { "servico": "Claude (assinatura)", "gasto": 100.00, "uso": 78 },
  { "servico": "API Claude (avulso)", "gasto":  35.00, "uso": 55 },
  { "servico": "Editor IA",            "gasto":  50.00, "uso": 20 }
]

Los valores son ejemplos. Usa los tuyos reales; para la API, consulta los precios oficiales. El servicio con uso bajo (aquí, 20%) es lo que el panel te indica para que reevalúes.

1

Enumera un elemento por servicio

Modelo/suscripción, gasto mensual y porcentaje de uso.

2

Pídele a Claude que sume y marque el subuso

Total del mes + alerta para los servicios de bajo uso.

3

Muestra el total y las alertas en el panel

De un vistazo decides si vale la pena mantener, descargar o cancelar un plan.

6

🚀 Onboarding y catálogo de skills/agentes

Dos piezas completan el sistema. El incorporación hace que Claude examine tu máquina (solo lectura), descubra las herramientas que usas y complete los datos iniciales. El catálogo mantiene un registro de cada skill y agente —con el modelo adecuado para cada tarea— para que nunca tengas que reinventar la rueda.

Qué es:

Onboarding = detección de herramientas en el PATH con confirmación antes de guardar. Catálogo = skills.json e agentes.json con nombre, descripción y modelo recomendado.

Por qué aprender:

El onboarding deja el sistema «listo para funcionar» en tu máquina sin tener que escribir nada manualmente; el catálogo evita que olvides lo que ya tienes.

Conceptos clave:

Comandos seguros de solo lectura · confirmación antes de escribir · un modelo potente para el razonamiento profundo y uno ligero para las tareas repetitivas · nada es fijo, todo se puede editar.

✓ Buenas prácticas de onboarding

  • ✓Detecta binarios en PATH y configuraciones conocidas — solo lectura.
  • ✓Muestra la lista y pide confirmación antes de guardar.
  • ✓Registrar en dados/ferramentas.json; lo que falte, lo agregas después.

✗ Qué evitar

  • ✗Dejar que Claude escriba sin que revises la lista.
  • ✗Catálogo sin el campo del modelo recomendado.
  • ✗Tratar lo que no se detectó como "imposible": solo hay que agregarlo.

Ejemplo de dados/skills.json (catálogo)

[
  { "nome": "revisar-texto", "faz": "revisa ortografia e clareza",
    "modelo": "leve (tarefa repetitiva)" },
  { "nome": "arquiteto", "faz": "planeja arquitetura de projeto",
    "modelo": "forte (raciocínio profundo)" }
]
Profundiza (opcional): metas y un agente de código abierto

Para darle más vida al sistema, registra metas de mediano plazo en un dados/metas.json que el panel muestra como progreso, y activa conhecimento/ como memoria a largo plazo. Si quieres conversar sobre tus metas, puedes conectar un agente open-source y gratuito — por ejemplo el Hermes Agent, totalmente opcional y sin costos ocultos. Nada de esto es obligatorio: el panel funciona muy bien por sí solo.

Autoevaluación (opcional): ¿qué hace que el panel HTML pueda mantenerse actualizado mediante comandos en lenguaje natural?

🧪 Ejemplo práctico guiado

Crea una versión mínima funcional de tu OS personal, desde cero hasta tener el panel abierto en el navegador.

1. Crea la estructura

En la terminal o pidiéndole a Claude, configura meu-os/ con las subcarpetas y los JSON vacíos (usa el árbol del tema 2).

2. Abre meu-os/ en Claude Code

Indica a Claude la carpeta raíz.

3. Escribe el CLAUDE.md maestro

Usa el prompt 1. Incluye el mapa de carpetas y las reglas de mantenimiento.

4. Completa los datos

2–3 proyectos reales en projetos.json; tus suscripciones en custo.json; 3 skills en skills.json.

5. Genera el panel

Pide painel/index.html leyendo los tres JSON: tarjetas de proyectos, lista de skills y costo total con alerta de subuso.

6. Ábrelo en el navegador

Dos clics en painel/index.html. Deberías ver tus datos.

7. Prueba el mantenimiento

En un chat nuevo, pide: "Agrega el proyecto X y actualiza el panel." Si Claude edita el JSON correcto leyendo solo el CLAUDE.md, el sistema está funcionando.

✏️ Ejercicios

1. Construye la columna vertebral (fácil)

Crea la carpeta raíz con todas las subcarpetas y los archivos vacíos. Criterio: el árbol de carpetas existe y coincide con el ejemplo.

2. Escribe el CLAUDE.md maestro (medio)

Máximo ~250 palabras, con un mapa de carpetas y reglas de mantenimiento. Criterio: en un chat nuevo, Claude describe el sistema con solo leer este archivo.

3. Genera el panel mínimo (medio)

Haz el index.html mostrar proyectos, skills y costo a partir de los JSON. Criterio: se abre en el navegador y muestra tus datos reales.

4. Rastrea el costo real (medio)

Completa custo.json con tus suscripciones y marca la que menos usas. Criterio: el panel destaca el servicio subutilizado.

5. Comando de mantenimiento (difícil)

En un chat nuevo, pídele a Claude que agregue una skill nueva. Criterio: skills.json se actualiza y la skill aparece en el panel sin que tengas que editarla manualmente.

⌨️ Prompts listos

Pega estos en Claude Code apuntando a la carpeta meu-os/. Arman cada pieza del sistema. La base de datos completa está en la Biblioteca → Prompts.

1. Crear el CLAUDE.md maestro

Esta pasta é o meu "sistema operacional pessoal" para o Claude Code.
Crie um CLAUDE.md mestre, curto (~250 palavras), com:
- mapa de pastas (projetos, skills, agentes, conhecimento, dados, painel);

2. Generar el panel HTML simple

Crie painel/index.html: uma única página, sem framework e sem backend,
que carrega via fetch os arquivos dados/projetos.json, dados/skills.json
e dados/custo.json e mostra três blocos: cards de Projetos, lista de Skills
e resumo de Custo do mês. Deve abrir direto no navegador (file://).
Visual limpo e escuro. Comente o código.

3. Detectar herramientas instaladas (onboarding)

Vasculhe minha máquina e detecte quais ferramentas de IA e dev eu uso
(CLIs, editores, terminais, agentes). Use comandos seguros, só de leitura.
Me mostre a lista para eu confirmar antes de salvar.
Depois grave o resultado em dados/ferramentas.json.
O que não achar, eu adiciono depois.

4. Comando de mantenimiento del sistema

Vou pedir mudanças no meu OS pessoal (adicionar projeto, skill, custo ou meta).
Sempre leia o CLAUDE.md mestre primeiro, edite só o JSON correto em dados/
e me diga o que mudou. Se algo não existir, me pergunte antes de criar.

⚠️ Errores comunes

  • ✗Quererlo todo el día 1. Intentar reproducir un panel lleno de funciones de una sola vez. Corrige: empieza con una carpeta raíz + CLAUDE.md + tres bloques en el panel; crece según la demanda.
  • ✗Datos dispersos y sin formato. Guardar información en lugares aleatorios que el panel no lee. Corrige: centraliza en dados/ con JSON simple y consistente.
  • ✗Adivinar precios y gastos. Inventar valores en el seguimiento de costos. Corrige: usa solo lo que indiques o los precios oficiales.
  • ✗CLAUDE.md maestro inflado. Llenar de detalles que cambian todo el tiempo. Corrige: mantén ~250 palabras; los detalles van a los JSON y conhecimento/.
  • ✗Tratar el sistema como cerrado. Creer que es "todo o nada" y bloquearse cuando algo no se detecta. Corrige: todo es editable; lo que falte, lo agregas pidiéndoselo a Claude.
